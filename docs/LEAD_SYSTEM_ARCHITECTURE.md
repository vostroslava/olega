# Система заявок: Supabase сейчас, Google Drive позже

## Решение

На первом этапе Supabase — единственный серверный контур системы заявок.
Сайт отправляет данные только в Edge Function. Браузер не получает ключей базы,
не пишет в таблицы и не имеет доступа к файлам других клиентов.

Google Drive пока не участвует в процессе. Когда он понадобится, он подключается
как архивный слой без изменения формы, публичного API или клиентского интерфейса.

## Первый этап: рабочая система заявок

```text
Сайт
  -> site-api /lead (Supabase Edge Function)
  -> проверка и антиспам
  -> leads + lead_files + private Storage
  -> уведомление менеджеру
  -> защищённая админка
```

### Что происходит с заявкой

1. Клиент выбирает объект, заполняет контакты и при необходимости добавляет файл.
2. `site-api` проверяет origin, honeypot, согласие, телефон, тип и размер файла.
3. Функция применяет rate limit и идемпотентность через `clientRequestId`.
4. В `leads` создаётся одна заявка со статусом `new`.
5. Вложение сохраняется в приватный Supabase Storage, а в `lead_files` — только его метаданные.
6. Менеджер получает уведомление. Ошибка уведомления никогда не отменяет сохранение заявки.
7. Администратор меняет статус и ведёт работу по заявке.

### Статусы

`new` → `reviewed` → `contacted` → `qualified` → `won` / `lost`.

Отдельный статус `spam` нужен для ручной очистки воронки. Статус не должен
меняться автоматически из-за ошибки уведомления или AI-обработки.

### Данные и доступ

- Все таблицы с лидами закрыты RLS.
- Публичный сайт общается только с Edge Function.
- Storage bucket `lead-files` приватный: файл можно открыть только через защищённый административный маршрут.
- Service role и любые внешние ключи существуют только в secrets Edge Function или в серверном окружении.
- Вложения ограничиваются типами `JPG`, `PNG`, `WEBP`, `HEIC`, `PDF`, `DWG`, `DXF` и размером до 10 МБ.

### Уведомления

Порядок важен:

1. Сначала durable-запись заявки и файла.
2. Затем уведомление в Telegram или email.
3. Если уведомление не прошло, заявка остаётся видна в админке и помечается для повторной отправки.

## Админка

Админка — отдельная защищённая зона, а не скрытая страница публичного сайта.

Минимальный первый релиз:

- авторизация сотрудников;
- список заявок с фильтром по статусу;
- карточка заявки с контактами, параметрами и файлами;
- смена статуса;
- журнал событий: создана, уведомлена, статус изменён.

Первый администратор — отдельный bootstrap-доступ без видимой почты. Его логин
и пароль существуют только в Edge Function secrets; после первого успешного
входа функция создаёт внутреннюю Supabase Auth-учётную запись и фиксирует роль
`admin` в `staff_members`. Это не клиентская «заглушка»: каждый дальнейший
запрос всё равно проходит проверку Supabase-сессии и серверной роли.

Администратор создаёт сотрудников из раздела «Команда»: рабочая почта,
временный пароль, роль `manager`. Сотрудники не получают права управления
командой, а браузер по-прежнему не читает таблицы напрямую.

Для уведомлений отдельно нужны `TELEGRAM_BOT_TOKEN` и
`TELEGRAM_LEADS_CHAT_ID`. Ошибка уведомления не скрывает заявку.

## AI-контур

AI не должен быть условием приёма заявки.

Когда локальный worker включат, он берёт уже сохранённую заявку и создаёт
отдельный черновой разбор: категорию, полноту исходных данных, недостающие
вопросы и черновик ответа менеджера. Менеджер всегда подтверждает результат.

Если worker выключен, заявка и уведомление продолжают работать в обычном режиме.

## Добавление Google Drive позже

Публичный контракт не меняется: сайт по-прежнему отправляет заявку в `POST /lead`.

Добавляется внутренний архивный этап:

```text
Supabase lead + private file
  -> archive task
  -> папка Google Drive для заявки
  -> brief.md + вложения
  -> archive_status = archived
```

Для каждой заявки в Supabase будут храниться только технические архивные поля:

- `drive_folder_id`;
- `drive_folder_url`;
- `archive_status` (`pending`, `archived`, `failed`);
- `archived_at`;
- `archive_error_code` для повторной попытки.

После подтверждённой выгрузки можно включить политику хранения: Supabase остаётся
оперативным контуром на ограниченный срок, а Drive становится основным архивом.
Удаление или редактирование данных в Drive не должно автоматически удалять
заявку из Supabase — только через явную административную операцию.

## Порядок реализации

1. Проверить и развернуть существующую Supabase схему и `site-api`.
2. Подключить реальный `NEXT_PUBLIC_SITE_API_URL` к GitHub Pages.
3. Реализовать надёжные уведомления менеджеру.
4. Сделать защищённую админку заявок.
5. Провести тест: обычная форма, мастер расчёта, файл, дубль, ошибка уведомления.
6. Только после этого включать AI worker.
7. Отдельным этапом добавить Google Drive архиватор и проверку повторных попыток.

## Критерии готовности первого этапа

- Любая заявка появляется в админке даже при выключенном AI worker.
- Файл виден только авторизованному сотруднику.
- Повторная отправка с тем же `clientRequestId` не создаёт дубликат.
- Ошибка Telegram/email не приводит к потере заявки.
- На публичном сайте нет service role, ключа Drive или прямого доступа к таблицам.
